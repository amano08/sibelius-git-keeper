# Sibelius × GitHub 保全システム

Sibelius の譜面ファイル（.sib）を、保存のたびに GitHub の **private repo** へ自動で送り、版として残すための仕組みです。

保存したつもりでも実際にはファイルに書き込まれていなかった、という事故は実際に起きます（ネットワーク共有のマウントが外れた状態での保存など）。この仕組みでは、保存のたびにその時点の .sib が GitHub に残るので、過去の版をいつでも取り戻せます。

## 大事な前提

- 管理する repo は **必ず Private** です。Public では使えません（セットアップが public を検知すると停止します）
- 保全対象は **.sib 本体のみ** です。MusicXML や PDF は書き出しません
- 曲は、この repo の中で管理します。譜面のためだけに別の repo は作りません
- **force push は全面禁止** です。他のマシンで先に保存した版がある場合も、自動で上書きすることはありません

## フォルダの形

```
（この repo）
├─ README.md            このファイル
├─ LICENSE              MIT ライセンス
├─ AI_SETUP_PROMPT.md   AI エージェントにセットアップを任せるためのプロンプト
├─ AGENTS.md            この repo で作業するエージェント向けのルール
├─ _system/             道具領域（プラグイン、ヘルパー、セットアップ）
└─ my_songs/            既定の置き場
   └─ sample_song/      サンプル（試し運転用）
```

曲フォルダの形は次のとおりです。分類の階層は自由です。

```
my_songs/曲名/曲名.sib
仕事/曲名/曲名.sib
仕事/分類/曲名/曲名.sib
```

- 曲フォルダとは「直下に .sib があるフォルダ」のことです
- 曲フォルダには .gitignore が置かれ、既定では **.sib と .gitignore 以外は repo に上がりません**（同じフォルダに置いた mp3 や PDF が誤って上がるのを防ぎます）
- 他のファイルも保全したい場合は、その曲フォルダの .gitignore を自分で編集してください。.gitignore はあなたの持ち物で、更新で上書きされることはありません
- `_system` や `.` で始まる名前は予約です。曲名・分類名には使わないでください
- `my_songs` は既定の置き場というだけです。削除・改名・追加は自由です

## 導入手順

### 方法A：AI エージェントに任せる（おすすめ）

`AI_SETUP_PROMPT.md` のプロンプトを、自分の AI エージェント（Claude、Codex、ChatGPT など）に渡してください。端末で完結する作業はエージェントが行い、人の手が要る場面では1手順ずつ案内が出ます。

### 方法B：自分で進める

1. **repo を作る**：配布元 template repo のページで「Use this template」から新しい repo を作ります。可視性は **必ず Private** を選んでください。clone は SSH の URL で行います
2. **セットアップを実行する**：Sibelius を終了した状態で、clone 先で `_system/setup.sh` を実行します。プラグインの配置、対象 repo の登録、監視の登録、push の疎通確認（dry-run）までを行います
3. **Cmd+S を割り当てる**：下の「Cmd+S の割り当て」の手順で、プラグインのコマンドに Cmd+S を割り当てます
4. **試し運転**：`my_songs/sample_song/sample_song.sib` を開いて少し編集し、Cmd+S で保存します。GitHub の repo ページで commit が増えていることを確認してください。確認できたら導入完了です（サンプルフォルダは削除しても構いません）
5. **既存の譜面を取り込む**：保全したい譜面は、Sibelius で開いてプラグインの「管轄内へ取り込む」を使って曲フォルダへ移します。**譜面を開いたまま Finder でファイルを移動しないでください**（Sibelius が古い保存先へ書き戻す事故が起きます）。Finder で移すのは、譜面を閉じている場合だけにしてください
6. **日常の保存**：普段の保存は Cmd+S で行います。保存が完了すると、背面で commit と push が走ります

repo の外にある譜面で保存コマンドを実行した場合は、通常の保存のみが行われ、その旨の表示が出ます。

## Cmd+S の割り当て

1. Sibelius を起動します（プラグインの読み込みには、配置後の再起動が1回必要です）
2. 設定（環境設定）の「キーボードショートカット」を開きます
3. プラグインのカテゴリから「gitと併せて保存」を探します
4. ショートカットとして Cmd+S を割り当てます。既存の割り当てと競合する場合は、案内に従って置き換えてください

割り当てはあなたの設定を壊さないよう手動の1手順としています。ショートカット集のファイルを直接書き換える方法は使いません。

> 注意：この割り当て手順は試作段階のもので、画面の文言は Sibelius のバージョンにより異なる場合があります。

## 日常の使い方

- 保存は Cmd+S（またはプラグインのメニュー「gitと併せて保存」）で行います
- プラグインの「状態確認」で、開いている譜面が管轄内かどうか、未送信の commit 数、repo のサイズ、最後の push 時刻を確認できます
- オフラインで保存しても commit は手元に残り、接続が戻った後の保存時にまとめて push されます
- 「gitと併せて保存」を実行した場合は、その都度 commit が作られます。Sibelius は保存のたびに .sib ファイル全体を書き換えるため、編集していない保存でも commit が作られます。監視が拾う保存（ツールバーの保存ボタンなど）や keeper の手動実行では、ファイルが実際に変わっていない場合は commit は作られません

## 複数マシンで使う場合

同じ repo を複数マシンで使う場合は、**1台で編集して push し、他のマシンでは pull してから編集する**運用にしてください。同時編集は想定していません。向こうの版が新しい状態で保存しても、あなたの版はローカルの commit として残り、自動で上書きされることはありません。

## repo のサイズについて

保存のたびに .sib の版が増えるため、repo は時間とともに大きくなります。「状態確認」でサイズを確認できます。GitHub が推奨する repo サイズの範囲を超えないよう、大きくなりすぎた場合は古い版の整理を検討してください（v1 では自動のアーカイブ機能はありません）。

## 更新

`_system/setup.sh` の再実行が更新を兼ねます。差し替えられるのは `_system` とプラグインだけです。あなたの .gitignore、設定、曲フォルダには触れません。

なお、template から作った repo は template 側の改良を自動では受け取りません。新しい版が出たら、配布元の `_system` を取り込んでから setup.sh を再実行してください。

## アンインストール

`_system/uninstall.sh` を実行すると、プラグインと監視が取り除かれます。Cmd+S の割り当ては、あなたの設定であるため自動では戻しません。設定画面で通常の保存へ割り当て直してください。

repo、commit の履歴、譜面ファイルには一切触れません。やめた後も GitHub 上の版はそのまま残ります。

## 試作段階についての注意

このシステムは現在 **試作段階** です。ManuScript プラグインの実機検証は Sibelius 25.4（Mac）で完了していますが、他のバージョンや Windows では未検証です。プラグインが読み込めない、コマンドが動作しない等の場合は、無理に使い続けず、通常の保存と手動の git 操作で運用してください。
